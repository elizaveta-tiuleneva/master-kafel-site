# Архитектура: Supabase и админ-панель

Документ описывает, как будет устроен этап 3 (админ-панель) и как к нему подключатся
этапы 4 (DeepL) и 5 (заявки и Telegram). Код этих этапов ещё не написан.

## 1. Общая схема

```
Браузер посетителя ──► React-сайт ──(publishable key)──► Supabase
                                                         ├─ Postgres + RLS
Браузер администратора ─► /admin (тот же сайт) ─────────►├─ Auth (email + пароль)
                                                         ├─ Storage: project-photos (публ.)
                                                         │           lead-files (закрытое)
Форма заявки ──► Edge Function submit-lead (secret key) ─►├─ leads, lead-files
                         └──► Telegram Bot API           │
Кнопка «Перевести» ─► Edge Function translate ──► DeepL  └─ Secrets: DeepL, Telegram
```

- В браузер попадают только `VITE_SUPABASE_URL` и publishable key. Права ограничивает RLS.
- Секретные ключи (Supabase secret, DeepL, Telegram) живут только в Supabase → Edge Functions → Secrets.
- Единственная новая зависимость — `@supabase/supabase-js`. Загрузчик фото, сжатие,
  сортировка написаны без дополнительных библиотек.

## 2. База данных

Миграция: `supabase/migrations/20261102120000_initial_schema.sql`.

| Таблица | Назначение | Кто читает | Кто пишет |
|---|---|---|---|
| `admins` | список администраторов (user_id) | сам пользователь — свою строку | только через SQL Editor |
| `projects` | проекты портфолио, RU/KO поля | все — опубликованные; админ — все | админ |
| `project_photos` | фото: `before` / `after` / `gallery`, порядок `position` | все — фото опубликованных; админ — все | админ |
| `leads` | заявки с формы | админ | Edge Function `submit-lead` |
| `lead_files` | фото к заявкам | админ | Edge Function `submit-lead` |

Поля проекта (каждое текстовое — в двух языках, `_ru` и `_ko`):

| Поле | На сайте | Обязательно для публикации |
|---|---|---|
| `category` | фильтр, бейдж | да |
| `title` | заголовок карточки и страницы | да (RU и KO) |
| `district` | «Тэджон, Юсон-гу» | да (RU и KO) |
| `summary` | 2 строки на карточке | нет |
| `task` | «Исходная задача» | нет |
| `work` | «Выполненные работы» — каждая строка = пункт | нет |
| `result` | «Результат» | нет |
| `completed_on` | дата (показывается как «май 2026») | нет |
| `area_m2` | площадь | нет |
| `cover_photo_id` | главная фотография | нет (по умолчанию первое «После») |

База сама не даст опубликовать проект без названия и района на обоих языках
(ограничение `projects_publishable`), поэтому непереведённый проект случайно не попадёт на сайт.

Пары «До / После» составляются по порядку: первое «До» с первым «После» и т. д.
Лишние фото без пары показываются только в галерее.

**Перенос в рабочий проект:** в базе хранится путь файла (`projects/<id>/<uuid>.webp`),
а не полный адрес. Сайт собирает адрес из `VITE_SUPABASE_URL`, поэтому смена проекта
не требует правок в данных или коде.

## 3. Безопасность

- **RLS включён на всех таблицах.** Посетитель видит только `status = 'published'`.
- **Права администратора** — функция `is_admin()` проверяет таблицу `admins`. Простого входа
  в аккаунт недостаточно: пользователь без строки в `admins` ничего не видит и не меняет.
- **Регистрация отключена** в настройках Auth; учётные записи создаются вручную.
- **Заявки:** у посетителей нет прав ни на чтение, ни на запись таблицы `leads`.
  Запись — только серверной функцией, которая проверяет поля, тип и размер файлов,
  частоту отправки (по хэшу, не по самому IP) и скрытое поле-ловушку для ботов.
- **Хранилище:** `project-photos` — чтение по ссылке, запись только админом,
  WebP/JPEG/PNG до 5 МБ. `lead-files` — закрытое, файлы отдаются администратору по
  временной ссылке (10 минут), до 10 МБ, только изображения.
- **Двойная проверка файлов:** в браузере (тип, размер) и на сервере (лимиты корзины + функция).
- Секреты не попадают в код и в git: `.env.local` в `.gitignore`, в репозитории только `.env.example`.

## 4. Админ-панель

Отдельный простой интерфейс без публичных Header/Footer. Загружается только при
открытии `/admin` (lazy loading), поэтому посетители сайта его не скачивают.
Язык интерфейса — русский (владельцы пишут на русском).

### Страницы

| Адрес | Что там |
|---|---|
| `/admin/login` | email + пароль, «Войти» |
| `/admin` | список проектов |
| `/admin/projects/new` | новый проект |
| `/admin/projects/:id` | редактирование |
| `/admin/leads` | заявки (новые сверху, фильтр по статусу) |
| `/admin/leads/:id` | заявка: данные, фото, «Позвонить», статус, заметка |

Не вошедший пользователь всегда перенаправляется на `/admin/login`.

### Список проектов

Карточка-строка: обложка · название · категория · дата · статус
(🟢 «Опубликован» / ⚪ «Черновик»). Кнопки: **Изменить**, **Опубликовать / Снять с публикации**,
**Удалить** (с подтверждением «Удалить проект и все его фотографии?»).
Сверху — большая кнопка **+ Добавить работу**.

### Редактор проекта — один экран, блоки сверху вниз

1. **Основное** — категория (4 большие кнопки), район, дата, площадь.
2. **Тексты на русском** — название, краткое описание, задача, выполненные работы, результат.
3. **Кнопка «Перевести на корейский →»** (этап 4).
4. **Тексты на корейском** — те же поля, редактируемые. Пока DeepL не подключён — заполняются вручную.
5. **Фото «До»**, **Фото «После»**, **Дополнительные фото** — три отдельных блока, в каждом
   кнопка **Добавить фото** (на телефоне открывает камеру или галерею).
   У каждого фото: ↑ ↓ — порядок, ★ — сделать главной, 🗑 — удалить.
   Подсказка: «Первое фото «До» сравнивается с первым «После». Снимайте с одной точки».
6. **Нижняя панель** (закреплена): **Сохранить черновик** · **Предпросмотр** · **Опубликовать**.

Подписи простые, без технических терминов. Ошибки — понятным текстом
(«Не удалось загрузить фото: файл больше 20 МБ»). При уходе со страницы с несохранёнными
изменениями — предупреждение.

### Загрузка фотографий

1. Владелец выбирает фото (можно несколько сразу).
2. Браузер проверяет тип и размер (до 20 МБ исходника).
3. Браузер сжимает: поворот по EXIF, большая сторона до 2000 px → WebP; превью 800 px.
   Снимок с телефона 5–8 МБ → примерно 300–500 КБ. Метаданные EXIF (включая геолокацию)
   при этом удаляются.
4. Загрузка в `project-photos/projects/<id>/<uuid>.webp` с индикатором прогресса.
5. Запись строки в `project_photos`. Если запись не удалась — загруженный файл удаляется.

HEIC с iPhone: Safari при выборе фото обычно сам отдаёт JPEG. Если браузер не может открыть
файл — сообщение «Этот формат не поддерживается. Сохраните фото как JPEG».

Порядок фото меняется кнопками ↑ ↓: они одинаково удобны на телефоне и компьютере,
а перетаскивание на телефоне работает плохо и потребовало бы отдельной библиотеки.

### Удаление проекта

Сначала удаляются файлы из хранилища, затем строка проекта (фото удаляются каскадом).
Если файлы удалить не удалось — проект не удаляется, показывается ошибка.

### Предпросмотр

Открывает настоящую страницу `/portfolio/:id?preview` в новой вкладке. Для администратора
RLS разрешает читать черновик; сверху плашка «Черновик — посетители этого не видят».

### Заявки (подготовка к этапу 5)

Список: дата, имя, телефон, тип помещения, статус (Новая / В работе / Завершена / Спам).
В заявке: все поля, фото по временным ссылкам, кнопка **Позвонить** (`tel:`), заметка,
смена статуса, удаление. Отметка, дошло ли уведомление в Telegram.

## 5. Публичный сайт после подключения базы

- `src/data/projects.js` (демо) заменяется на `src/api/projects.js` с теми же функциями:
  список опубликованных, проект по id, похожие проекты. Компоненты страниц почти не меняются.
- Добавляются состояния загрузки (скелетоны), ошибки («Не удалось загрузить. Повторить»)
  и пустого портфолио — сейчас они уже есть в разметке для пустого списка.
- Подробная страница получает разделы «Задача / Выполненные работы / Результат» вместо одного описания.
- Если переменные Supabase не заданы, сайт в режиме разработки показывает демо-данные —
  так дизайн можно проверять без базы.

## 6. Структура файлов (план этапа 3)

```
src/
  lib/supabase.js            клиент Supabase из переменных окружения
  lib/photoUrl.js            путь в хранилище → публичный адрес
  lib/imageResize.js         сжатие фото в браузере (canvas → WebP)
  api/projects.js            чтение проектов для сайта
  api/adminProjects.js       создание/изменение/удаление, фото, порядок, обложка
  api/adminLeads.js          заявки для админки
  admin/
    AdminApp.jsx             маршруты /admin/*, загружается лениво
    AuthProvider.jsx         сессия + проверка is_admin
    RequireAdmin.jsx
    AdminLayout.jsx          простая шапка: «Работы», «Заявки», «Выйти»
    pages/LoginPage.jsx
    pages/ProjectsPage.jsx
    pages/ProjectEditPage.jsx
    pages/LeadsPage.jsx
    pages/LeadPage.jsx
    components/PhotoSection.jsx    блок «До» / «После» / «Доп. фото»
    components/PhotoTile.jsx       фото с кнопками ↑ ↓ ★ 🗑
    components/BilingualFields.jsx поля RU / KO
    components/ConfirmDialog.jsx
supabase/
  migrations/20261102120000_initial_schema.sql   ✅ готово
  snippets/add-admin.sql                          ✅ готово
  functions/translate/      этап 4
  functions/submit-lead/    этап 5
.env.example                                      ✅ готово
```

Изменятся существующие файлы: `src/App.jsx` (маршрут `/admin/*` и `/privacy`),
`src/pages/PortfolioPage.jsx`, `src/pages/ProjectDetailsPage.jsx`, `src/components/ProjectCard.jsx`
(данные из базы), `package.json` (+ `@supabase/supabase-js`).
`HomePage.jsx`, `Header.jsx`, `Footer.jsx` не меняются.
